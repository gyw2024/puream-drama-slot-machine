# BUG-100：H3 两句原生对白、场景原图与无 ASR 验收边界不统一

## 现象

- 单条 H3 任务可能塞入多轮对白，也可能把每句拆成过多付费碎片，导致说话人、嘴型和台词归属不稳定。
- 当前剧本对白可能被复用为人物音色校准内容，文本和音频同时携带词句，给 H3 两套冲突的台词来源。
- 场景四视图可能在供应商分块阶段进入共用裁图逻辑，H3 收到的不是用户确认的完整场景原图。
- 成片阶段仍存在 ASR 转写脚本与验收口径，前序已经锁定的对白又被后验识别结果二次裁决。

## 深层根因

1. 剧本对白账本、H3 供应商任务和剪辑节拍没有形成单一边界，旧系统提示还允许 2–5 轮问答。
2. 人物音色资产的“声线身份”和当前任务的“准确台词”没有隔离，人物校准句曾回退到 `signatureLine` 或剧本对白。
3. 逐秒分镜合图与人物、商品、场景参考共用一个裁切判断，分块时没有按参考类型决定是否可裁。
4. 过去用成片 ASR 补偿提示词和说话人控制不足，导致后验检查反过来成为流程依赖。

## 根修复

- 每条 H3 供应商任务最多两句完整对白：同一人物可连续说两句，两人对话可各说一句；第三句进入下一条任务，句内永不切断。
- 每句准确中文文本只在 H3 `<d>[Chinese] ...</d>` 标签出现一次；人物图绑定唯一 Subject、镜头拥有者和嘴型拥有者。听者必须闭口并作可见反应。
- 不为当前对白生成音频。可选音色资产只能使用与剧情隔离的中性校准句，H3 无音频时直接依据人物图和准确文本原生说话。
- 场景四视图始终以一个完整、原样的文件跨越供应商边界；裁切只允许作用于真正的逐秒分镜合图。
- 删除成片 ASR/转写脚本及运行时入口；前序提示词、对白账本、参考绑定和媒体解码构成唯一验收链。
- 最终视频提示词不再写逐句秒点或“第几秒前说完”，但继续保留情绪、声调、表情、动作、站位、朝向、自然切镜和场景连续性。
