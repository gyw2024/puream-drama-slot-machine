# BUG-105：资产前提示词全文显示与统一确认边界

## 用户现象

- 单镜分镜视频提示词窗口只显示到约 500 字，长提示在句中被切断。
- 资产前总弹窗中的英文执行稿标题显示完整长度，但展开后实际仍只有前 500 字。
- 对白审计中的结构化语气偶发显示为 `[object Object]`。
- UI/IPC 已做确认预检，但内部、恢复或批量调用仍可能先执行依赖整理，再发现提示词尚未确认。

## 最深层根因

1. `maskSpecificModelText()` 原本只为错误摘要设计，会压平空白并执行 `.slice(0, 500)`；单镜创作提示词错误复用了该函数。
2. 即使总弹窗组件写入了完整英文执行稿，全局 MutationObserver 仍会遍历 `<pre>`，再次调用同一个 500 字错误摘要函数。
3. 不同文本模型可能把语气返回为对象；对白账本预览直接 `String(object)`，因此产生 `[object Object]`。
4. 资产前确认只在渲染层和主进程预检，`generateAllAssets`、`generateAllStoryboards`、`generateAllShotVideos` 自身没有在任何依赖或付费边界前统一断言。

## 修复

- 新增创作提示词全文通道，完整保留原始换行和全部字符；错误摘要继续独立维持 500 字公开显示上限。
- 将提示词总弹窗、单镜编辑窗和示例窗设为创作原文保护区，全局品牌脱敏观察器不得改写其中任何文本或属性。
- 总弹窗同时标出完整中文稿与英文执行稿的准确字符数；长文本在等高卡片内部滚动，不设置 `maxlength`，尾部可达。
- 新增结构化表演字段扁平化，只抽取语气、情绪、音量、语速、重音、呼吸等有效字段并去重。
- 三个批量工作流入口在依赖解析、并发申请或付费提交之前统一调用 `assertPromptReviewApproved()`；直接调用、恢复调用和 UI 调用遵守同一边界。

## 验证

- 专项：`scripts/full-prompt-preasset-v114-regression.test.js`，`4/4`。
- 相关提示词/简易模式回归：`34/34`。
- 全量源码回归：`709/709`。
- Headless UI 对抗审计：7 组视口与缩放，交互 `8/8`；每个中文稿均超过 500 字并校验尾标，英文执行稿 1783 字全文与尾标完整可见。
- 未调用任何付费图片、视频或文本接口；未使用桌面自动化。
