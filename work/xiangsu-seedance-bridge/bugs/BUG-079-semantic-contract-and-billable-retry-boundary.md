# BUG-079：语义锁定、正文编译与计费重试边界

## 现象

长剧正文阶段曾收到未闭合的 JSON，并提示已锁定镜头缺失。受影响项目中，语义 S10 同时有 1、2、3 三名说话人；正文合同却要求可见人物最多两人且每名说话人都必须可见。此前失败处理又将每次错误作为新正文创作请求，产生大量独立的付费会话。

## 根因

1. 语义合同允许同一镜三名说话人，正文合同限制两名，两个阶段不存在可满足的交集。
2. 语义阶段已经写出并锁定最终台词、前后状态和切点，正文阶段仍要求模型重新输出相同台词及表演扩展字段。这个重复序列化的响应很长，模型输出被截断时 JSON 自然未闭合；逐字锁定又使任何改写都不能通过。
3. 通用上游 `PROVIDER_HTTP_ERROR` 没有解读响应正文的余额/鉴权语义，余额耗尽被误判为可恢复的创作失败；每次修复使用新 session id，形成无上限独立计费。
4. 原测试只用完整的假 JSON，没有覆盖三人同镜、真实输出截断、通用 HTTP 余额正文或重复无效响应。

## 修复

- 语义阶段和正文阶段统一限制为每镜最多两名说话人，并在语义检查时验证台词轮次及字数预算。
- 正文阶段改为本地 `buildDirectFastSemanticSegment` 编译已锁定的语义单元；不再调用模型重写已锁定台词。
- 语义截断续补复用同一 provider session，并把已锁定单元随 stateless 请求带回；每个五镜范围仅允许一次自动续补，第二次仍无效则保留断点并等待明确继续。
- 上游通用 HTTP 错误会读取正文；余额、额度、鉴权、API Key、禁用 billing 等立即停止，绝不重试。
- 回归测试覆盖三人同镜拒绝、锁定台词逐字保留、本地正文零模型调用、Kimi 风格余额正文及语义截断续补。
