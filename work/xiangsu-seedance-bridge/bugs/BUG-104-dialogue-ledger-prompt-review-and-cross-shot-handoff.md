# BUG-104：对白丢失/错人、跨镜跳变与资产前确认旁路

## 用户症状

1. 对白剧情出现丢失、重排或人物归属错乱。
2. 单镜提示词出现人物名，却没有该人物的说话内容。
3. 相邻镜头的站位、动作、服装、道具和情绪跳变。
4. 部分剧本入口在资产生成前没有弹出全部提示词确认窗。
5. 单镜窗口只能看到一段不完整编译稿，无法逐句核对对白归属。

## 最深层根因

- 原稿对白账本、镜头 `dialogueTurns`、Foundry `productionIR` 和中英文执行稿是多份可独立变旧的副本；后写入者可能覆盖正确原稿。
- Foundry 过去只用原始剧本文本判断缓存是否有效，镜头结构变化但 `raw` 不变时会继续使用旧 IR。
- 独立“分析剧本/生成完整剧本”入口未复用一键流程的资产前提示词确认门。
- 提示词确认状态混入候选资产和运行进度，抽卡后可能被误判为失效。
- 单镜编辑器没有把不可变对白账本作为独立、可见的核对层。

## 修复

- 以 `script.sourceDialogueLedger` 为唯一对白事实源，在每个提示词边界重新绑定镜头，并确定性补齐遗漏说话人。
- Foundry 增加结构化制作源指纹；镜头对白、状态、场景或资产事实变化会重建 IR。
- 中英文提示词共用同一 canonical shot；旧 IR 的对白签名不一致时禁止覆盖当前账本。
- 两个独立剧本入口统一调用 `requestPromptReview`，资产前必须进入总确认窗。
- 提示词确认采用“创作事实指纹 + 设置指纹”，排除候选、任务、进度和已选资产等运行态。
- 单镜窗口显示逐句对白审计与完整提示词，增加内部滚动、字符计数和 100000 字符编辑容量。
- H3 提示词增加跨镜承接，并将内部 C/P/SC 编号绑定为实际 Subject/参考语义，避免把内部编号泄漏给上游。

- 根因专项 `5/5`，历史相关回归 `57/57`，全量回归 `705/705`。
- Headless UI 审查 7 组，交互 `8/8`，无 serious/critical 可访问性问题。
