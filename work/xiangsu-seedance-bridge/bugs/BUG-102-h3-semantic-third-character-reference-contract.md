# BUG-102：H3 合法第三人物引用被旧两人校验器误拦截

## 现象

- 提示词编译已经为有明确剧情任务的第三名人物绑定身份图，但在正式提交前报错：`人物身份图绑定重复或不属于本镜可见人物：C03`。
- 同一镜头的提示词、参考图预览与付费提交对“本镜人物”的判断不一致，用户无法继续生成视频。

## 最底层根因

1. `shotReferences()` 已扩展为按对白、动作承受者、递物对象和反应角色保留最多四名语义必要人物。
2. `assertStrictCharacterMediaBindings()` 仍调用旧的 `visibleShotCharacterCast()`；该函数为控制单个画面主体数量，会把当前机位裁成两名主要可见人物。
3. 因此编译器合法加入的 C03 在下一层被校验器当成“额外人物”，形成软件内部自相矛盾，而不是 H3 上游拒绝或系统提示词写错。
4. 旧单测只覆盖“两个人物”和“重复图片”，没有覆盖“第三名语义人物合法入镜、但每个机位仍最多突出两张脸”的组合场景。

## 根修复

- 新增唯一权威的 `shotReferenceCharacterIds(project, shot)`：合并说话人、当前主要可见人物、动作/递物/反应等语义人物和原稿显式人物，并过滤为项目真实人物，H3 最多保留四名。
- 提示词参考规划、确认页清单、严格提交校验和实际 provider 提交全部使用该同一集合，不再各自推导。
- 机位层仍只突出最多两名主要人物；第三/第四名只在剧情需要的时间段入镜，并由导演阻塞规则限定位置、朝向和反应，避免群像挤占主体。
- 重复身份图仍是错误：专项回归同时验证合法 C03 可通过、同一 C03 重复绑定仍会被拒绝。
