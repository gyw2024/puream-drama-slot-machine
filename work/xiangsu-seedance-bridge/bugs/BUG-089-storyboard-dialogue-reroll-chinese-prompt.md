# BUG-089：复合分镜引用、对白人物绑定、重抽旧指针与视频提示词展示分裂

## 现象

- 视频主要停留在分镜合图前几格，没有完整执行鞋子、走位和后续反应画面。
- 双人同框时，本应由 A 说的对白被 B 说出。
- 已经生成过 9:16 分镜合图，点击“再抽一次”却提示缺少分镜合图并终止。
- 提示词确认页与后续视频提示词编辑窗口有的显示英文、有的显示不完整中文，用户无法稳定修改。

## 最深层根因

1. 视频提交链把多格分镜合图当作一个普通参考图；提示词虽然描述时间线，上游却没有获得“第几秒对应哪一格”的独立图片绑定。用户附件为正方形 4×2 合图，单格实际是 1:2，也不是项目要求的 9:16。
2. 旧对白合同只把台词文本附在人物附近，没有把稳定人物编号同时绑定到说话人口型、说话人机位、人物音色和闭口听者；双人同框时上游可以自行交换嘴型或声线。
3. 重抽链只读取上一次的 `selected` 候选路径。旧选中文件被替换、迁移或清理后，即使同一制作版本仍有有效合图，也被误判为完全没有参考图。
4. 提示词确认和后续编辑分别消费翻译结果、系统执行稿和手动稿，缺少唯一的结构化中文展示数据源；翻译未返回或旧项目字段不齐时就出现中英混排。

## 修复

- 新合图拓扑让整张画布与每个小格均使用项目画幅；9:16 的 8 格采用 3×3、10 格采用 4×4，空位不改变单格比例。
- 视频提交前按声明或实际分隔线确定性裁切分镜合图，去除分隔边缘，生成独立 360×640 图片；每张图带有精确起止时间和父合图血缘，按时间顺序提交，裁切失败时安全沿用原图而不拦截用户。
- 每句对白生成稳定合同：`speaker=Cxx`、指定说话人口型与机位、对应音频、闭口听者及精确台词窗口；中文编辑稿同步清晰显示同一绑定关系。
- 重抽优先使用真实存在的当前候选；选中路径失效时自动回退到同一制作版本仍存在的候选，再重新预处理分镜序列。
- 增加本地结构化中文视频提示词渲染器。两个用户入口都显示同一份纯中文编辑稿，内部英文执行稿独立保存；修改中文后由提交链更新执行稿。

## 验证

- 用户附件 4×2 合图实际裁成 8 张独立 360×640 图，顺序 1—8，至少 6 个不同 SHA-256。
- 专项回归 4/4；完整仓库回归 636/636。
- UI 无头运行矩阵覆盖 1024×720、1280×800、1440×900、1920×1080 与 200% 缩放；顺序、尺寸、滚动、中文编辑、稍后恢复、Axe 严重问题与页面异常全部通过。
