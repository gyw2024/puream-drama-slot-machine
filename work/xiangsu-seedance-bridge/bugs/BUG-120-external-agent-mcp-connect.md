# BUG-120：外部 Agent 无法配置并接入短剧老虎机 MCP

## 现象

系统只有内部 MCP 控制能力，没有向用户提供外部 Agent 所需的连接参数；安装版直接把 ASAR 内脚本当作 Node 入口也无法稳定启动。用户因此既看不到配置，也无法判断应该填写 URL、端口或令牌。

## 根因

1. 产品边界没有明确：短剧老虎机应作为本机 MCP 服务端，通过 stdio 被外部 Agent 拉起，而不是要求用户连接一个 HTTP 地址。
2. 打包边界缺失：开发环境脚本路径可读，不代表安装后的 ASAR 虚拟路径能被外部 Node 进程作为真实入口使用。
3. 设置页缺少可发现性：已有内部控制通道，但没有把启动命令、参数、客户端配置和握手状态产品化。
4. 全局文案脱敏规则过宽，把包含“连接”的正常标签当成网络错误改写，造成 UI 语义错误。
5. 用户数据审计直接打开活动 SQLite/WAL，审计动作本身可能创建或更新共享内存文件，违反只读验收预期。

## 根因修复

- 增加解包到 `resources/mcp` 的真实 MCP stdio 启动入口，安装版 `--mcp-stdio` 只走该入口。
- 增加统一客户端配置生成器，输出通用 JSON 与 Codex TOML；配置只包含可执行文件和 `--mcp-stdio`，不暴露内部控制密钥。
- 设置页展示服务状态、命令、参数、两种配置以及一键复制和真实握手检测。
- 将文案规则缩窄为明确的失败短语，不再匹配普通“连接”文本，并增加永久回归测试。
- 用户数据审计复制数据库、WAL、SHM 到隔离临时目录后执行 quick_check；归档目录只做字节哈希。

## 验证证据

- 外部 MCP 实际握手：`puream-drama-workbench`，stdio，35 个工具，版本 0.16.171，可读取 55 个现有项目。
- 安装前后用户数据清单完全一致：2901 个文件、319 个目录、11984248332 字节；新增、删除、修改均为 0。
- 全量测试：933 项，932 通过，0 失败，1 项按设计跳过。
- 官网 r153 生产构建及 16 组受保护能力门禁通过；公网回下载安装包的大小和 SHA-256 与本地正式包一致。
