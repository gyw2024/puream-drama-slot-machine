# BUG-101：H3 最终导演载荷丢失因果、表演、运镜与实体参考

## 现象

- 成片人物语气偏平，句内没有清楚的声调、呼吸、重音和表情变化。
- 相邻台词缺少可见前因与结果，故事虽有原句但听起来像孤立念词。
- 双人对白大多停留在固定双人中景，换说话人后没有形成有动机的正反打。
- 同一人物或关键道具可能被复制；群戏中的未绑定角色可能被模型补成主角分身或相似脸。
- 换发色、换装等剧情状态与人物参考的“锁定服装/头发”规则互相冲突。

## 深层根因

1. 最终 provider 编译器优先取简短 `deliveryEn`，没有把完整 `vocalArcEn`、`expressionEn`、`speakerFacingEn`、`blockingEn` 与 `listenerReactionEn` 作为同一逐句表演合同。
2. 英文字段按字符窗口截断，形成 `make one direct`、`holding the damaged` 等残句；重复通用模板占用长度，关键导演信息反而丢失。
3. 多处把 `visibleCharacterIds` 和视频人物参考固定裁成 2 人；动作、状态仍可引用第三名及更多已命名人物，最终载荷出现未绑定实体。
4. 道具识别只匹配中文名称，不读取 `P01` 等稳定 ID、英文动作/状态和 provider 时间线；普通道具图又只写成匿名 `locked prop appearance`。
5. 人物身份图同时锁脸、头发和服装，未区分永久身份与剧本明确要求的发色/换装状态。
6. 原稿声音提示没有与导演 Agent 的通用 `soundEn` 合并，剪刀、摔物、门铃、撕纸、拍桌和掌声等剧情落点可能从最终提示词消失。

## 根修复目标

- 最终提交稿以“状态前因 → 可见动作 → 精确逐句表演 → 听者反应 → 状态结果”为唯一顺序。
- 每句保留完整声线弧、表情、身体动作、站位朝向和听者反应，并用简洁结构减少重复模板。
- 为所有实际引用的人物、场景、服装、商品和道具生成稳定的 `Subject/Scene/Prop/Product/Picture/Audio` 一一映射。
- 人物永久身份只锁脸、年龄和体态；发色与服装只在本镜未发生明确变化时延续。
- 每名主体在同一画面只有一个物理实例；匿名群像必须与主角具有不同脸、体态和服装，并保持闭口。
- 换说话人时用明确的说话人机位所有权和直接正反打；群像动作使用有动机的独立反应镜头。
- 原稿可见动作声与环境声进入最终 provider 声场合同，不增加成片后验拦截或自动付费重试。
