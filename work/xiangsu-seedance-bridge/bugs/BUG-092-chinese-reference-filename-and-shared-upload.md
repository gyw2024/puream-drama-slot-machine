# BUG-092：中文参考图文件名在发包前失败，并被误报为网络波动

## 用户症状

- 不含商品的分镜首帧正常生成；商品出现后的连续六个镜头同时缺少 9:16 首帧。
- 界面显示参考素材上传可重试或连续性参考缺失，看起来像官网/网络故障。
- 图片供应商没有收到这六个请求，因此没有产生对应生图费用。

## 最深层根因

1. 管理型临时存储把 `path.basename(filePath)` 原样写进 `x-puream-file-name`。
2. 客户商品图文件名包含中文。Fetch 的请求 Header 值是 ByteString，中文字符在网络连接建立前就触发 `Cannot convert argument to a ByteString`。
3. 上传错误分类器把所有 `TypeError` 一概当成网络错误，掩盖了确定性的协议编码错误。
4. 图片参考上传没有复用视频上传已有的“同一文件共享上传 Promise”设计；多个商品镜头会并发重复上传同一张本地图。
5. 工作流直接使用全局 Fetch，未显式继承 Electron `net.fetch` 的系统代理与证书栈。

## 根修复

- `x-puream-file-name` 改为 UTF-8 百分号编码后的纯 ASCII 值，扩展名保持可识别；极长名称退化为哈希文件名并保留扩展名。
- 只有真实连接/超时/Socket 特征或可重试 HTTP 状态才归类为网络错误，不再把任意 `TypeError` 吞成网络波动。
- `WorkbenchWorkflow` 注入 Electron `net.fetch`，Agent 与简易模式统一使用系统代理和证书栈。
- 按“存储范围 + 文件 SHA-256”共享进行中上传和一小时内的成功 URL；六个镜头引用同图只上传一次。
- 上游建任务前的瞬时上传失败使用同一请求标识自动恢复，最多六次指数退避，且支持用户取消。

## 真实验收

- 文件：`七味堂植物泡泡染发膏-3D93262537EC.png`，1,686,064 bytes。
- 修复前真实探针：12–16ms 内本地失败，HTTP 状态 0，请求未离开客户端。
- 修复后真实探针：2,358ms 返回 HTTP 200 和有效 HTTPS 地址。
- 定向回归：14/14 通过，覆盖中文 Header、同图并发合并、预连接失败恢复、上传状态分类、全流程提示词重入。
- 完整真实项目继续从 S22–S27 六张缺失首帧断点续跑；此前 25 张首帧全部复用。
