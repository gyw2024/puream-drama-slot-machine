# BUG-076

- 现象：一键生成时，上游返回半截选题或半截剧本 JSON，界面直接显示失败；已返回的有效条目没有保留，也没有自动补齐。
- 根因：新入口仍把外层 JSON 解析失败当作终局失败，未提取已闭合对象，也未进入 AI 缺口修复流程。该问题是 BUG-001、BUG-017、BUG-019 的同类复发。
- 修复版本：0.16.35
- 修复：对截断响应扫描并保留完整对象；选题保留有效条目后由 AI 只补缺；语义切镜保留完整 `u` 单元后按索引补齐；不使用固定本地选题替代 AI。
- 状态：源码已修复，待外部回归测试确认。

## 2026-08-20 correction — v0.16.40

- 新证据：DeepSeek `deepseek-v4-flash` 的 450 秒语义切镜响应在 S14 的 `duration` 字段中断；连接没有完整 SSE 终止帧。旧代码把该前缀当作成功文本，再以笼统的 `SCRIPT_SEMANTIC_SCHEDULE_CONTRACT_FAILED` 拒收，既不能区分上游截断，也要求一次性返回约 45 镜。
- 根因修正：所有 OpenAI 兼容供应商现在必须收到 `[DONE]` 或 `finish_reason` 才视为完成；未终止流保留原始前缀并报告 `PROVIDER_STREAM_INCOMPLETE`。长剧语义切镜改为五镜一段、固定精确时长、逐段检查点与缺段续写，不重写已通过的镜头。
- 验证：新增流中断和分段续写回归；全量 `node --test scripts/*.test.js` 419/419 通过。待安装包外部真实供应商回归确认。

## 2026-08-20 correction — v0.16.41

- 续补策略下沉到通用结构化文本入口：所有文本供应商只要返回可识别的半截 JSON，系统都会把原始前缀作为对话上下文追加给上游，并要求只补剩余 JSON 字符；若上游返回完整替代根对象则直接采用。
- 循环只会在用户取消或供应商返回余额、鉴权、配置等没有 JSON 前缀的明确阻断时停止；流中断、输出上限和 JSON 截断不再形成项目断点。

## 2026-08-20 correction — v0.16.42

- 根因闭环：兼容 OpenAI 协议的供应商曾把 `reasoning_content` 当作可交付正文；当 Kimi、DeepSeek 或其他推理模型只完成思考而未给最终内容时，解析器会从思考里引用的 JSON 示例中误取对象，造成“请求成功但业务镜头为零”。
- 修复：正式 `content` 与推理字段彻底隔离；流式 UI 仅显示正式正文。无正文、说明文本或非 JSON 返回统一走干净的 JSON 重试，绝不把推理、提示词或示例传回作为续写内容。Kimi 结构化请求固定低推理强度；DeepSeek 保持结构化禁用思考策略。
- 语义切镜：非最后镜禁止提前写“全剧收束/结束/定格”；历史检查点也会重新校验并只重写发生提前收尾的范围。范围补齐不再在三次后中断，直到成功、用户取消或明确余额/鉴权/配置阻断。
- 验证：Kimi reasoning-only、DeepSeek/OpenAI 兼容流、Gemini、Anthropic 非 JSON 回包，以及连续三次无效语义范围后的第四次恢复，均由离线模拟回归覆盖。
