# BUG-118 Codex 资产包执行模式混淆

## 用户可见问题

- 用户通过 `.pdramapack` 导入了 Codex 已准备好的完整资产和逐镜提示词，软件却把项目显示成“资产直投”。
- 包内 `shot_anchor` 被存成 `storyboard_start`，使界面和后续判断把镜头级合成参考误称为“首帧”。
- 实际没有“单首帧模式”，但错误的内部映射让用户无法判断视频究竟走了哪条链路。

## 根因

1. 资产包导入只是一个文件入口，没有被建模为独立生产模式。
2. 导入器把 `generation.mode` 和每镜 `videoStrategy` 硬编码为 `asset_direct`。
3. 为复用候选图渲染，`shot_anchor` 被降格映射到 `storyboard_start`，语义血缘随之丢失。
4. 资产、分镜图、提示词编辑和视频提交边界没有针对导入合同做只读隔离。

## 根因修复

- 新增第一类 `production_package` 模式，并在模式选择页明确展示“Codex 资产包直抽”。
- `shot_anchor` 作为独立候选阶段持久化；它是包声明的整镜头合成参考，不是首帧、尾帧、关键帧或资产直投身份板。
- 旧版已导入项目在读取/保存时确定性迁移：`asset_direct` 改为 `production_package`，包内锚点从 `storyboard_start` 改回 `shot_anchor`，普通资产直投项目完全不迁移。
- 导入后的剧本、人物、场景、核心物品、逐镜提示词与图片顺序只读锁定；资产和分镜图阶段硬返回零生成。
- 上游只接收包内精确英文提示词和原顺序图片，不传参考音频，不传上一镜视频。
- 每镜提交前持久化一次性边界；任何已有提交尝试、任务号或供应商任务证据都会阻止第二次提交。

## 回归边界

- 普通 `asset_direct` 仍是不生成分镜图、按人物/场景/道具身份资产组装提示词的独立模式。
- `production_package` 不在应用内重编剧本、提示词或资产，也不把 `shot_anchor` 当成需要生成的分镜图。
- 全项目提交前先一次性校验全部镜头；若任一镜头提示词、说话人或引用不合法，则零上游提交。
- 修复测试只做零付费预检与隔离用户数据的真实导入，不创建新的视频任务。
