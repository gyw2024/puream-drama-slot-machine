## 根因

旧架构把“一条业务分镜”直接等同于“一次视频供应商任务”。业务分镜包含多人问答时，同一提示词同时要求多个说话人、多个机位和内部切镜；模型往往保留首个视觉主体，于是对白已换人，镜头、视线和嘴型仍留在上一人。父级分镜合图也沿用首个角色的画格，导致提示词中的“切镜”没有对应视觉锚点。

## 结构修复

- `app/agent-director.js` 是 H3 导演合同的单一权威：从不可变对白账本生成原子镜头；说话人或机位变化就是供应商任务边界。
- 每个原子镜头只有一个 `cameraOwner`、一个 `mouthOwner` 和一名说话人；画外音不占嘴型，监听者保持闭口。
- 多帧合图先生成原子镜头画格表，在说话人边界强制换画格；提交视频时只裁取当前原子镜头的连续画格。
- H3 提示词采用官方六段结构；中文只进入 `<d>[Chinese] ...</d>` 对话块，并在付费提交前验证 1900 字符预算、对白顺序、机位、嘴型和表演六要素。
- 全片在第一笔视频费用前完成全部 Agent 镜头计划、参考图裁切、音色绑定和最终提示词预检。
- 本地精确硬切、缺失音轨补静音以及按原剧本时长拼接，消除供应商尾帧漂移。
- 全局 `AdaptiveProductionAgent` 统一调度文本、图片、视频提交、视频查询与导演镜头计划；旧 IPC 不再绕过 Agent 直连供应商。
- 正式创作路径不再以本地固定剧情、固定对白、固定资产或固定分镜代替 AI；失败时保留断点，继续任务只恢复失败的 Agent 单元。

## 输出硬合同

- 严禁字幕、标题、姓名条、价格字、水印、界面文字、人物介绍、故事简介和资产板进入成片。
- 严禁背景音乐；只允许剧中对白、连续环境声和画面内真实同步动作声。
- 上传剧本的对白文字、顺序和说话人保持不可变；Agent 只负责生产化解析、表演、调度和镜头控制。
