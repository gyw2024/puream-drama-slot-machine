# 0.14.0 正式版

本版不是继续叠补丁，而是在不改变用户熟悉的生产流程和主体界面的前提下，引入 **PUREAM Adaptive Drama Compiler V2**。它把剧本、资产、分镜、视频与成片从松散 JSON 流程升级为“单一制作合同 + 本地确定性预编译 + 可审计事务状态 + 分级质量门”的模块化单体架构。

## 底层架构

- 每个项目生成不可含糊的制作合同：原稿处理方式、带货方式、速度/质量偏好、时长、引擎、输出禁令和质量等级均进入同一个版本化指纹。
- `SQLite` 成为当前项目状态的权威源；JSON 继续作为兼容镜像。每次保存都有压缩修订快照、审计事件、检查点与可重试操作记录，旧镜像不能再覆盖新状态。
- 一键全流程和一步步做剧调用同一个工作流、同一个阶段状态机和同一套质量门；分步模式只停在用户指定阶段，一键模式才会连续跨阶段。
- 本地机械兜底只能恢复结构、给出诊断，未达到正式质量门时不得继续消耗图片和视频费用。

## 剧本与剧情

- 先在本地识别格式、正文边界、场景出现顺序、人物、逐句对白、商品事实和用户说明，再把结构化证据交给模型；附件中的说明永远不能覆盖软件的绝对安全合同。
- 用户上传原稿设为最高事实权威。尊重原稿、智能优化、重新创作三种方式分别锁定不同边界，人物介绍与故事简介只作上下文，不进入剧情时间线。
- 原稿场景账本和逐句对白账本贯穿资产、分镜、视频与终审；漏场、并场、换人说台词、改写对白、丢结局会在付费生成前失败关闭并指出缺项。
- 不带货、自然植入、明确带货三种模式独立于剧本格式；未提供商品时自动归零，禁止系统凭空编造商品功效、价格或购买引导。

## 资产与出片

- 人物、场景、音色、分镜图和视频都建立资产护照：来源、实体、阶段、文件指纹、依赖指纹、当前版本和审核状态可追溯；同一实体只有一个明确的当前资产。
- 人物四视图固定使用全画布统一 `#E9E9E9` 背景，正面、左侧 90°、右侧 90°、背面全身站立；禁止肖像大头、烟雾、渐变、拼贴文字和黑边。
- 成片硬性禁止字幕、标题、人物介绍、角标、水印、界面字和背景音乐。这些禁令位于提供商提示词之上，并由最终质量门再次检查。
- 质量报告分 L1 结构、L2 连贯、L3 正式交付；正式流程要求剧情闭环、来源场景覆盖、对白归属、资产依赖和机器禁令同时通过。

## 使用与存储

- 新建项目和“调整制作策略”沿用原弹窗，只增加三个紧凑选择项：原稿处理、带货方式、优先目标；用户不需要学习一套新界面。
- 每次点击“一键生成 10 个选题”都创建新的请求代次，并结合历史标题、批次指纹和本地多池轮换避免重复返回上一批。
- 安装程序保留自定义安装目录；系统设置中的保存位置迁移会检查点数据库、复制全部数据、重写数据库及 JSON 内的绝对路径、`file://` 与 `puream-asset://` 地址，校验完成后才切换并重启。旧目录始终保留，不做删除。

## 兼容与迁移

- 首次启动自动把历史项目导入 V2 事务库，迁移可重复执行且不会生成重复修订。
- JSON 镜像损坏时优先从 SQLite 当前状态恢复；用户已删除的项目不会因数据库残留而复活。
- 原有项目、素材库、历史候选、费用记录、失败记录、设置及所有生产功能继续保留。

## 性能根因修复

- 独立资产库索引一旦建立即作为权威目录直接读取，不再在每次启动时遍历全部项目、重复哈希和复制数百个大文件。
- 首次建库只读取每个项目一次、在内存中批量去重并一次性提交索引；侧栏按人物/场景类型请求，图片懒加载，视频不预读媒体元数据。
- 正式安装态验收把真实客户资产库打开时间纳入 5 秒硬门槛，超时即不得判定发布合格。

## 发布门槛

- 全量自动回归、真实客户剧本解析、历史项目隔离迁移、保存位置迁移、打包态多分辨率/高缩放 UI、真实素材像素解码与安装态审计必须全部通过。
- 验收不提交任何付费图片或视频任务，不覆盖客户项目，不删除旧数据。
